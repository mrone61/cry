Cara Kerja Sistem

CryptoSecure Vault menjamin dua aspek utama keamanan: kerahasiaan dan keutuhan data. Dilindungi ML-KEM-768 + Argon2id + AES-256-GCM & SHA-512, sesuai Standar Post-Quantum NIST FIPS 203.

1. ML-KEM-768 Hybrid - Pertukaran Kunci Anti-Kuantum

Sebelum password dikirim, browser dan server melakukan pertukaran kunci menggunakan ML-KEM-768 Hybrid (X25519 + SHA3-512), sesuai standar NIST FIPS 203. Ini adalah algoritma Post-Quantum resmi yang dirancang untuk tahan terhadap serangan komputer kuantum, termasuk Algoritma Shor yang mampu membobol RSA / ECC. Endpoint /kem-public dan /kem-handshake menangani proses ini.

2. Kunci Super - Password + Kunci Server (Wajib dari ENV)

Password yang kamu ketik tidak langsung dipakai. Password digabung dengan Kunci Rahasia Server yang wajib di-set lewat Environment Variables PythonAnywhere. Tidak ada lagi kunci cadangan di dalam kode. Jika kunci server tidak di-set, web sengaja tidak akan berjalan demi keamanan. Jadi meskipun ada yang tahu password kamu, tanpa Kunci Server dia tetap tidak bisa membuka.

3. Argon2id - Pemenang Password Hashing Competition

Kunci enkripsi dibuat menggunakan Argon2id (time=3, memory=64 MB, parallelism=4). Argon2id tidak hanya membuat CPU capek seperti PBKDF2 lama, tapi juga membuat RAM capek, sehingga hacker yang memakai GPU / ASIC untuk brute-force jadi tidak berguna. Ini adalah standar terbaik saat ini untuk mengolah password.

4. Enkripsi Teks - AES-256-GCM (Anti-Kuantum)

Pesan teks dienkripsi menggunakan AES-256-GCM, sesuai Standar Post-Quantum NIST. Menggunakan kunci 256-bit sehingga meskipun diserang komputer kuantum dengan Algoritma Grover, kekuatannya masih setara AES-128 dan tetap mustahil dibobol. Setiap pesan memakai Salt 32 byte + Nonce acak yang baru, jadi pesan yang sama akan menghasilkan token yang selalu berbeda. Format token baru diawali PQv3. yang sudah berisi waktu kedaluwarsa.

5. Enkripsi File - AES-256-CTR + HMAC-SHA512 Streaming

Untuk file (Gambar, Audio, Video, PDF, CSV), sistem memakai AES-256-CTR + HMAC-SHA512 mode Streaming. File dibaca per 64 KB, dienkripsi per potong, tidak pernah diload 20 MB sekaligus ke RAM. Saat didekripsi, file langsung di-download dengan nama asli agar browser tidak berat. Maksimal ukuran file 20MB. Format baru diawali FILEv3.

6. Dekripsi - Verifikasi Sebelum Dibuka

Sistem memverifikasi HMAC-SHA512 / GCM terlebih dahulu. Jika valid dan kunci sesuai, pesan atau file dikembalikan ke bentuk asli. Jika ada satu karakter saja yang diubah pada token, sistem akan menolak dan menganggap token rusak / password salah.

7. Token Hangus 1x Pakai + Database Permanen - Burn After Reading

Setiap token hanya bisa dibuka 1x saja. Begitu berhasil dibuka, sidik jari token (SHA-256) langsung dimasukkan ke database SQLite (vault.db) dan dimusnahkan. Berbeda dengan versi lama yang masih di RAM, sekarang token hangus tetap hangus walau server restart / reload. Jika token yang sama dicoba dibuka lagi, sistem akan menolak dengan pesan "Token ini SUDAH HANGUS".

8. Token Kedaluwarsa 24 Jam

Setiap token hanya berlaku 24 Jam sejak dibuat. Jika tidak dibuka dalam 24 jam, token otomatis hangus dengan pesan "Token ini SUDAH KEDALUWARSA". Ini seperti fitur disappearing message di WhatsApp / Telegram, agar token lama yang bocor tidak bisa dipakai selamanya.

9. Anti Brute Force - Hukuman Bertingkat + Blokir Global

Sistem menghitung percobaan gagal per IP + per Token, dan juga per IP Global. Jika salah password 3x, token langsung terkunci. Hukumannya bertingkat dan makin lama:

- Gagal 3x = Terkunci 1 Menit
- Gagal 6x = Terkunci 1 Jam
- Gagal 9x = Terkunci 1 Hari
- Gagal 12x = Terkunci 7 Hari
- Gagal 15x = Terkunci 30 Hari
- Gagal 20x dalam 1 Jam di token apapun = Blokir Global IP 1 Jam (VPN / ganti token tidak berguna)

10. Password Wajib Kuat

Saat enkripsi, password wajib memenuhi syarat: minimal 8 karakter, harus ada huruf BESAR (A-Z), huruf kecil (a-z), dan angka (0-9). Contoh password kuat: Rahasia123. Password lemah seperti `123` atau `abc` akan langsung ditolak, karena kunci AES-256 akan sia-sia jika passwordnya mudah ditebak.

11. Keamanan Server & Ketahanan Kuantum

AES-256 merupakan standar enkripsi yang digunakan di perbankan dan instansi pemerintah, dan dinyatakan Quantum-Resistant oleh NIST. Komputer kuantum dengan Algoritma Grover hanya mampu memotong kekuatan kunci menjadi setengah, sehingga AES-256 tetap aman. Sedangkan Algoritma Shor yang mampu membobol RSA / ECC tidak berpengaruh ke sistem ini karena Vault tidak menggunakan RSA sama sekali, melainkan ML-KEM-768. Input file dibatasi maksimal 20 MB untuk mencegah penyalahgunaan server.

12. Token Lama Tidak Berlaku

Sejak upgrade ke standar Anti-Kuantum, token lama (PQv2 / FILEv2, Fernet / AES-128 dan HMAC-SHA256) tidak dapat lagi dibuka. Silakan buat token baru dengan format PQv3. untuk teks dan FILEv3. untuk file.
